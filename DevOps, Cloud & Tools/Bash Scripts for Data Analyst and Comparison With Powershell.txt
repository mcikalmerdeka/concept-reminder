# Useful Bash Scripts for Data Analysts and Data Scientists

Here are several practical Bash scripts that can help with data-related tasks, along with explanations of what they do and how to use them:

## 1. Data File Organizer

```bash
#!/bin/bash

# Create organized directory structure for a data project
mkdir -p data/{raw,processed,interim}
mkdir -p results/{figures,tables}
mkdir -p scripts
mkdir -p notebooks
mkdir -p docs

echo "Data project structure created successfully!"
```

**What it does**: Creates a standardized directory structure for organizing data projects.

**How to run**: 
1. Save this script as `setup_project.sh`
2. Make it executable with `chmod +x setup_project.sh`
3. Run it in your project directory with `./setup_project.sh`

**Where to use**: When starting a new data analysis project to maintain consistent organization.

## 2. CSV File Processing

```bash
#!/bin/bash

# Process all CSV files in a directory
# Usage: ./process_csv.sh <input_directory> <output_directory>

INPUT_DIR=$1
OUTPUT_DIR=$2

# Check if directories exist
if [ ! -d "$INPUT_DIR" ]; then
    echo "Input directory does not exist!"
    exit 1
fi

# Create output directory if it doesn't exist
mkdir -p "$OUTPUT_DIR"

# Process each CSV file
for file in "$INPUT_DIR"/*.csv; do
    if [ -f "$file" ]; then
        filename=$(basename "$file")
        echo "Processing $filename..."
        
        # Remove header, sort by second column, and save to output
        tail -n +2 "$file" | sort -t, -k2 > "$OUTPUT_DIR/sorted_$filename"
        
        echo "Created $OUTPUT_DIR/sorted_$filename"
    fi
done

echo "All CSV files processed!"
```

**What it does**: Takes all CSV files from an input directory, removes headers, sorts them by the second column, and saves the results to an output directory.

**How to run**:
1. Save as `process_csv.sh`
2. Make executable with `chmod +x process_csv.sh`
3. Run with `./process_csv.sh input_folder output_folder`

**Where to use**: When you need to quickly preprocess multiple CSV files in batch.

## 3. Data Backup Script

```bash
#!/bin/bash

# Backup data to a timestamped directory
# Usage: ./backup_data.sh <directory_to_backup>

# Configuration
BACKUP_DIR="/path/to/backups"
SOURCE_DIR=$1
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")

# Create backup filename
BACKUP_FILE="$BACKUP_DIR/backup_$TIMESTAMP.tar.gz"

# Create backup directory if it doesn't exist
mkdir -p "$BACKUP_DIR"

# Perform the backup
echo "Backing up $SOURCE_DIR to $BACKUP_FILE"
tar -czf "$BACKUP_FILE" "$SOURCE_DIR"

# Check if backup was successful
if [ $? -eq 0 ]; then
    echo "Backup completed successfully!"
    echo "Backup saved to: $BACKUP_FILE"
else
    echo "Backup failed!"
fi
```

**What it does**: Creates a compressed backup of a specified directory with a timestamp.

**How to run**:
1. Save as `backup_data.sh`
2. Make executable with `chmod +x backup_data.sh`
3. Edit the `BACKUP_DIR` variable to set your preferred backup location
4. Run with `./backup_data.sh /path/to/your/data`

**Where to use**: For regular backups of important datasets or project files.

## 6. Log File Analyzer

```bash
#!/bin/bash

# Analyze log files to extract errors and statistics
# Usage: ./analyze_logs.sh <log_file>

LOG_FILE=$1

if [ ! -f "$LOG_FILE" ]; then
    echo "Log file does not exist!"
    exit 1
fi

echo "Analyzing log file: $LOG_FILE"
echo "--------------------------"

# Count total lines
TOTAL_LINES=$(wc -l < "$LOG_FILE")
echo "Total log entries: $TOTAL_LINES"

# Count and extract errors
echo "Error summary:"
grep -i "error" "$LOG_FILE" | cut -d' ' -f3- | sort | uniq -c | sort -nr

# Count warnings
WARNING_COUNT=$(grep -i "warning" "$LOG_FILE" | wc -l)
echo "Total warnings: $WARNING_COUNT"

# Extract timestamp of first and last entry
FIRST_TIMESTAMP=$(head -n 1 "$LOG_FILE" | cut -d' ' -f1,2)
LAST_TIMESTAMP=$(tail -n 1 "$LOG_FILE" | cut -d' ' -f1,2)

echo "Log time span: $FIRST_TIMESTAMP to $LAST_TIMESTAMP"
```

**What it does**: Analyzes a log file to extract statistics, errors, and warnings.

**How to run**:
1. Save as `analyze_logs.sh`
2. Make executable with `chmod +x analyze_logs.sh`
3. Run with `./analyze_logs.sh path/to/logfile.log`

**Where to use**: When you need to quickly analyze application logs to find errors or issues.

## 7. Model Training Monitor

```bash
#!/bin/bash

# Monitor a long-running model training process and send notification when complete
# Usage: ./monitor_training.sh <pid>

MODEL_PID=$1

if [ -z "$MODEL_PID" ]; then
    echo "Please provide a process ID to monitor"
    echo "Usage: ./monitor_training.sh <pid>"
    exit 1
fi

echo "Monitoring model training process (PID: $MODEL_PID)..."

# Check if the process exists
if ! ps -p $MODEL_PID > /dev/null; then
    echo "Process with PID $MODEL_PID does not exist!"
    exit 1
fi

# Monitor the process until it completes
while ps -p $MODEL_PID > /dev/null; do
    echo "Training in progress... ($(date))"
    sleep 60  # Check every minute
done

# Process has completed
END_TIME=$(date)
echo "Model training completed at $END_TIME!"

# Send desktop notification (Linux)
if command -v notify-send &> /dev/null; then
    notify-send "Model Training Complete" "Your model training process has finished at $END_TIME"
fi

# Create a completion log
echo "Model training completed at $END_TIME" > training_complete.log
```

**What it does**: Monitors a long-running process (like model training) and notifies you when it completes.

**How to run**:
1. Save as `monitor_training.sh`
2. Make executable with `chmod +x monitor_training.sh`
3. Start your model training in a separate process
4. Run with `./monitor_training.sh <pid>` where `<pid>` is the process ID of your training job

**Where to use**: When running time-consuming model training jobs that you want to monitor without continuously checking.

# Running Bash Scripts on Windows

Yes, you can run Bash scripts on Windows, but you'll need to set up the right environment first. Here are your options:

## Option 1: Windows Subsystem for Linux (WSL)
This is the most powerful and recommended approach:

1. **Install WSL**:
   - Open PowerShell as Administrator
   - Run: `wsl --install`
   - Restart your computer when prompted
   - Complete the Ubuntu setup (default Linux distribution)

2. **Run your scripts**:
   - Open Ubuntu terminal (from Start menu)
   - Navigate to your scripts
   - Run them using `./scriptname.sh`

## Option 2: Git Bash
If you don't want to install WSL:

1. **Install Git for Windows**:
   - Download from [https://git-scm.com/downloads](https://git-scm.com/downloads)
   - This includes Git Bash, a minimal Bash environment

2. **Run your scripts**:
   - Right-click in a folder and select "Git Bash Here"
   - Run scripts using `./scriptname.sh`

## Option 3: Cygwin
A more comprehensive Unix-like environment:

1. **Install Cygwin**:
   - Download from [https://www.cygwin.com/](https://www.cygwin.com/)
   - Select packages during installation

2. **Run your scripts**:
   - Open Cygwin terminal
   - Navigate to your scripts
   - Run using `./scriptname.sh`

## Option 4: Convert to PowerShell
If you prefer staying in native Windows:

- PowerShell is actually quite powerful and can do many things Bash can
- You could convert the Bash scripts to PowerShell scripts
- Example: the directory creation script in PowerShell would be:

```powershell
# PowerShell equivalent of the directory creation script
New-Item -Path "data\raw", "data\processed", "data\interim", "results\figures", "results\tables", "scripts", "notebooks", "docs" -ItemType Directory -Force
Write-Output "Data project structure created successfully!"
```

## Which option should you choose?

- **For data science work**: WSL is highly recommended as it gives you a full Linux environment
- **For simple scripts**: Git Bash is lightweight and easy to install
- **For Windows integration**: PowerShell might be better for Windows-specific tasks

# Bash vs PowerShell: Comparison for Data Professionals

Here's a side-by-side comparison of Bash and PowerShell scripts for common data tasks, highlighting the key differences in syntax, approach, and capabilities.

## 1. Directory Structure Creation

**Bash:**
```bash
#!/bin/bash

# Create organized directory structure for a data project
mkdir -p data/{raw,processed,interim}
mkdir -p results/{figures,tables}
mkdir -p scripts
mkdir -p notebooks
mkdir -p docs

echo "Data project structure created successfully!"
```

**PowerShell:**
```powershell
# Create organized directory structure for a data project
New-Item -Path "data\raw", "data\processed", "data\interim", "results\figures", "results\tables", "scripts", "notebooks", "docs" -ItemType Directory -Force

Write-Output "Data project structure created successfully!"
```

**Key Differences:**
- PowerShell uses `New-Item` with `-ItemType Directory` instead of `mkdir`
- PowerShell uses backslashes (`\`) for paths while Bash uses forward slashes (`/`)
- Bash uses the `-p` flag to create parent directories; PowerShell uses `-Force`
- PowerShell generally uses more verbose command names that follow a Verb-Noun pattern

## 2. Processing CSV Files

**Bash:**
```bash
#!/bin/bash

# Process all CSV files in a directory
INPUT_DIR=$1
OUTPUT_DIR=$2

# Create output directory if it doesn't exist
mkdir -p "$OUTPUT_DIR"

# Process each CSV file
for file in "$INPUT_DIR"/*.csv; do
    if [ -f "$file" ]; then
        filename=$(basename "$file")
        echo "Processing $filename..."
        
        # Remove header, sort by second column, and save to output
        tail -n +2 "$file" | sort -t, -k2 > "$OUTPUT_DIR/sorted_$filename"
        
        echo "Created $OUTPUT_DIR/sorted_$filename"
    fi
done
```

**PowerShell:**
```powershell
# Process all CSV files in a directory
param (
    [string]$InputDir,
    [string]$OutputDir
)

# Create output directory if it doesn't exist
New-Item -Path $OutputDir -ItemType Directory -Force | Out-Null

# Process each CSV file
Get-ChildItem -Path $InputDir -Filter "*.csv" | ForEach-Object {
    $filename = $_.Name
    Write-Output "Processing $filename..."
    
    # Remove header, sort by second column, and save to output
    $content = Get-Content $_.FullName | Select-Object -Skip 1 | Sort-Object {
        $_.Split(',')[1]  # Sort by second column
    }
    
    $outputPath = Join-Path $OutputDir "sorted_$filename"
    $content | Set-Content $outputPath
    
    Write-Output "Created $outputPath"
}
```

**Key Differences:**
- PowerShell uses `param()` block for parameters instead of positional `$1`, `$2`
- PowerShell uses `Get-ChildItem` (alias: `dir` or `ls`) instead of shell globbing (`*.csv`)
- PowerShell uses `ForEach-Object` (alias: `foreach` or `%`) for iteration instead of Bash's `for` loop
- Bash pipes (`|`) operate on text; PowerShell pipes operate on objects
- PowerShell uses `Join-Path` to reliably combine paths

## 3. Data Backup

**Bash:**
```bash
#!/bin/bash

# Backup data to a timestamped directory
BACKUP_DIR="/path/to/backups"
SOURCE_DIR=$1
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")

# Create backup filename
BACKUP_FILE="$BACKUP_DIR/backup_$TIMESTAMP.tar.gz"

# Create backup directory if it doesn't exist
mkdir -p "$BACKUP_DIR"

# Perform the backup
echo "Backing up $SOURCE_DIR to $BACKUP_FILE"
tar -czf "$BACKUP_FILE" "$SOURCE_DIR"

# Check if backup was successful
if [ $? -eq 0 ]; then
    echo "Backup completed successfully!"
    echo "Backup saved to: $BACKUP_FILE"
else
    echo "Backup failed!"
fi
```

**PowerShell:**
```powershell
# Backup data to a timestamped directory
param (
    [string]$SourceDir
)

$BackupDir = "C:\path\to\backups"
$Timestamp = Get-Date -Format "yyyyMMdd_HHmmss"

# Create backup filename
$BackupFile = Join-Path $BackupDir "backup_$Timestamp.zip"

# Create backup directory if it doesn't exist
New-Item -Path $BackupDir -ItemType Directory -Force | Out-Null

# Perform the backup
Write-Output "Backing up $SourceDir to $BackupFile"

try {
    Compress-Archive -Path $SourceDir -DestinationPath $BackupFile -Force
    Write-Output "Backup completed successfully!"
    Write-Output "Backup saved to: $BackupFile"
} catch {
    Write-Output "Backup failed!"
    Write-Output $_.Exception.Message
}
```

**Key Differences:**
- PowerShell uses `Get-Date` with formatting instead of the `date` command
- PowerShell uses `Compress-Archive` for zip compression vs. Bash's `tar`
- PowerShell uses try/catch blocks for error handling instead of checking return codes
- PowerShell uses `.zip` format by default while Unix typically uses `.tar.gz`

## 4. Data Download and Processing

**Bash:**
```bash
#!/bin/bash

# Download dataset, extract it, and prepare for analysis
# URL of the dataset
DATASET_URL="https://archive.ics.uci.edu/ml/machine-learning-databases/iris/iris.data"

# Create directories
mkdir -p data/raw
mkdir -p data/processed

# Download the dataset
echo "Downloading dataset..."
curl -o data/raw/iris.csv "$DATASET_URL"

# Add header to the CSV
echo "Adding header to CSV..."
echo "sepal_length,sepal_width,petal_length,petal_width,class" > data/processed/iris.csv
cat data/raw/iris.csv >> data/processed/iris.csv
```

**PowerShell:**
```powershell
# Download dataset, extract it, and prepare for analysis
$DatasetUrl = "https://archive.ics.uci.edu/ml/machine-learning-databases/iris/iris.data"

# Create directories
New-Item -Path "data\raw", "data\processed" -ItemType Directory -Force | Out-Null

# Download the dataset
Write-Output "Downloading dataset..."
Invoke-WebRequest -Uri $DatasetUrl -OutFile "data\raw\iris.csv"

# Add header to the CSV
Write-Output "Adding header to CSV..."
$header = "sepal_length,sepal_width,petal_length,petal_width,class"
$content = Get-Content -Path "data\raw\iris.csv"
@($header) + $content | Set-Content -Path "data\processed\iris.csv"
```

**Key Differences:**
- PowerShell uses `Invoke-WebRequest` instead of `curl` (though PowerShell also has a `curl` alias)
- PowerShell handles file content as arrays of strings rather than using text redirection (`>`, `>>`)
- PowerShell creates arrays using `@()` syntax
- PowerShell uses `+` operator to concatenate arrays

## 5. Log Analysis

**Bash:**
```bash
#!/bin/bash

# Analyze log files to extract errors and statistics
LOG_FILE=$1

# Count total lines
TOTAL_LINES=$(wc -l < "$LOG_FILE")
echo "Total log entries: $TOTAL_LINES"

# Count and extract errors
echo "Error summary:"
grep -i "error" "$LOG_FILE" | cut -d' ' -f3- | sort | uniq -c | sort -nr

# Count warnings
WARNING_COUNT=$(grep -i "warning" "$LOG_FILE" | wc -l)
echo "Total warnings: $WARNING_COUNT"
```

**PowerShell:**
```powershell
# Analyze log files to extract errors and statistics
param (
    [string]$LogFile
)

# Count total lines
$totalLines = (Get-Content $LogFile).Count
Write-Output "Total log entries: $totalLines"

# Count and extract errors
Write-Output "Error summary:"
Get-Content $LogFile | Where-Object { $_ -match "error" -i } | 
    ForEach-Object { ($_ -split ' ',3)[2] } | 
    Group-Object | Sort-Object Count -Descending | 
    Format-Table Count, Name -AutoSize

# Count warnings
$warningCount = (Get-Content $LogFile | Where-Object { $_ -match "warning" -i }).Count
Write-Output "Total warnings: $warningCount"
```

**Key Differences:**
- PowerShell uses objects and methods like `.Count` instead of commands like `wc -l`
- PowerShell uses the pipeline differently, passing whole objects between commands
- PowerShell uses `Where-Object` and `-match` instead of `grep`
- PowerShell's `Group-Object` combines the functionality of `sort | uniq -c | sort -nr`
- PowerShell has rich formatting commands like `Format-Table`

## Philosophy and Approach Differences

### Object-Oriented vs Text-Based
- **Bash**: Operates on text streams, manipulating them with text-processing tools like `grep`, `sed`, and `awk`
- **PowerShell**: Operates on .NET objects with properties and methods, allowing for more structured data handling

### Consistency
- **Bash**: Commands have diverse syntax conventions due to their independent origins
- **PowerShell**: Uses consistent Verb-Noun naming convention (e.g., `Get-Content`, `Set-Content`)

### Error Handling
- **Bash**: Uses exit codes and requires explicit checking
- **PowerShell**: Supports structured exception handling with try/catch blocks

### System Integration
- **Bash**: Native to Linux/Unix systems, excellent for text processing
- **PowerShell**: Deeply integrated with Windows, excellent for Windows-specific tasks and .NET Framework

### Learning Curve
- **Bash**: Simpler syntax for basic tasks, but can become complex with advanced scripting
- **PowerShell**: Steeper initial learning curve, but more consistent with more advanced features

## Which is Better for Data Professionals?

**Use Bash when:**
- Working primarily in Linux/Unix environments
- Performing text processing or simple pipeline operations
- Working with traditional data processing tools (Python, R, etc.)
- Need compatibility with systems that may not have PowerShell

**Use PowerShell when:**
- Working primarily in Windows environments
- Need deep integration with Windows services or .NET
- Working with structured data where object properties are important
- Need advanced error handling and debugging capabilities

Many data professionals benefit from knowing both, using each where it's most appropriate.
