## 1. How trained ML models are saved (industry practice)

### ✅ Common formats (by model type)

#### **Classical ML (scikit-learn, XGBoost, LightGBM)**

Most common in industry:

| Format                     | When used             | Notes                                              |
| -------------------------- | --------------------- | -------------------------------------------------- |
| **joblib** ✅               | sklearn models        | Faster & safer than pickle for numpy-heavy objects |
| **pickle**                 | legacy / simple cases | Less preferred (security + performance concerns)   |
| **model-specific formats** | xgboost / lightgbm    | Often preferred                                    |

**Best practice**

```python
import joblib
joblib.dump(model, "model.joblib")
```

Why joblib?

* Handles large numpy arrays efficiently
* Standard for sklearn pipelines
* Widely accepted in production

---

#### **Deep Learning (PyTorch / TensorFlow)**

| Framework       | Preferred format            |
| --------------- | --------------------------- |
| PyTorch         | `.pt` / `.pth` (state_dict) |
| TensorFlow      | SavedModel directory        |
| Cross-framework | **ONNX** ⭐                  |

Example (PyTorch):

```python
torch.save(model.state_dict(), "model.pth")
```

---

#### **Production-grade, framework-agnostic**

If portability matters:

### ⭐ **ONNX**

* Works across Python, C++, Java
* Used in high-performance inference systems
* Supported by Azure, AWS, NVIDIA Triton

## 2. How models are actually served (important part)

### ❌ What *not* to do

* Let users run your notebook
* Re-load model every request
* Directly expose raw pickle files

---

### ✅ Industry-standard serving pattern

```
User Input
   ↓
API (FastAPI / Flask)
   ↓
Preprocessing (same as training)
   ↓
Loaded Model (in memory)
   ↓
Prediction
   ↓
JSON Response
```

---

### 🔹 Typical inference stack (Python)

#### **API layer**

Most common:

* **FastAPI** ⭐⭐⭐ (industry favorite)
* Flask (older, still used)

Example:

```python
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.joblib")

@app.post("/predict")
def predict(features: list[float]):
    prediction = model.predict([features])
    return {"prediction": prediction.tolist()}
```

Why FastAPI?

* Very fast
* Auto-generated Swagger UI
* Built-in validation (Pydantic)

---

#### **Preprocessing**

**Critical rule**:
👉 **Save preprocessing with the model**

Best way:

```python
from sklearn.pipeline import Pipeline

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", RandomForestRegressor())
])
```

Then save **the pipeline**, not just the model:

```python
joblib.dump(pipeline, "pipeline.joblib")
```

This is **100% industry best practice** for sklearn.

## 4. End-to-end “industry standard” workflow

Here’s what most real teams do:

1. Train model (sklearn / PyTorch)
2. Wrap preprocessing + model into pipeline
3. Save with **joblib / native format**
4. Create inference API (FastAPI)
5. Containerize with Docker
6. Deploy to cloud (Cloud Run / ECS / Render)
7. Monitor latency, errors, drift
