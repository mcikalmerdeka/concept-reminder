# Classes vs Functions: A Data Science/AI Engineering Perspective

Let me break this down with practical examples you'd actually encounter.

## Use Functions When:

**You need a one-off transformation or calculation**

```python
def preprocess_text(text):
    """Simple text cleaning"""
    text = text.lower().strip()
    text = re.sub(r'[^\w\s]', '', text)
    return text

def calculate_f1_score(precision, recall):
    """Single calculation"""
    return 2 * (precision * recall) / (precision + recall)
```

These are stateless operations - you give input, get output, done. No need to remember anything between calls.

## Use Classes When:

**You need to maintain state or configuration across multiple operations**

```python
class TextPreprocessor:
    def __init__(self, lowercase=True, remove_stopwords=True):
        self.lowercase = lowercase
        self.remove_stopwords = remove_stopwords
        self.stopwords = set(['the', 'a', 'an']) if remove_stopwords else set()
        
    def fit(self, texts):
        """Learn vocabulary from training data"""
        self.vocab = set()
        for text in texts:
            self.vocab.update(text.split())
        return self
    
    def transform(self, texts):
        """Apply learned preprocessing"""
        processed = []
        for text in texts:
            if self.lowercase:
                text = text.lower()
            words = [w for w in text.split() if w not in self.stopwords]
            processed.append(' '.join(words))
        return processed
```

Here the class remembers its configuration (`lowercase`, `stopwords`) and learned state (`vocab`). This follows the scikit-learn pattern you're probably familiar with.

**Class approach** - complex ML pipeline:
```python
class ModelTrainer:
    def __init__(self, model, optimizer, device='cuda'):
        self.model = model
        self.optimizer = optimizer
        self.device = device
        self.history = {'train_loss': [], 'val_loss': []}
        
    def train_epoch(self, train_loader):
        self.model.train()
        total_loss = 0
        for batch_x, batch_y in train_loader:
            batch_x = batch_x.to(self.device)
            batch_y = batch_y.to(self.device)
            
            self.optimizer.zero_grad()
            loss = self.model(batch_x, batch_y)
            loss.backward()
            self.optimizer.step()
            total_loss += loss.item()
        
        avg_loss = total_loss / len(train_loader)
        self.history['train_loss'].append(avg_loss)
        return avg_loss
    
    def save_checkpoint(self, path):
        torch.save({
            'model_state': self.model.state_dict(),
            'optimizer_state': self.optimizer.state_dict(),
            'history': self.history
        }, path)
```

The class here manages the entire training lifecycle - it holds the model, optimizer, tracks history, and provides related methods that all work together.

## Quick Decision Framework:

- **Function**: Stateless transformation, single responsibility, used once
- **Class**: Multiple related operations, needs to remember things (state), follows a lifecycle (fit/transform, train/predict)

In data science, you'll notice most preprocessing follows the class pattern (like scikit-learn's `StandardScaler`, `TfidfVectorizer`) because they need to "learn" from training data and apply the same transformation to test data. But individual metric calculations or data loading utilities are usually functions.

# Critical Concepts for Classes in Data Science/AI

## 1. **The `self` Parameter - What It Actually Means**

```python
class FeatureEngineering:
    def __init__(self, scaling_method='standard'):
        self.scaling_method = scaling_method  # Instance variable
        self.mean_ = None  # Will store fitted values
        self.std_ = None
    
    def fit(self, X):
        # 'self' lets you access the instance's own data
        self.mean_ = X.mean()
        self.std_ = X.std()
        return self  # Common pattern: return self for chaining
    
    def transform(self, X):
        # Using the stored mean/std from fit()
        return (X - self.mean_) / self.std_
```

**Key point**: `self` is how each instance remembers its own data. When you create `scaler1 = FeatureEngineering()` and `scaler2 = FeatureEngineering()`, they have separate `mean_` and `std_` values.

## 2. **Instance Variables vs Class Variables**

```python
class ModelRegistry:
    # CLASS variable - shared by ALL instances
    all_models = []
    
    def __init__(self, model_name):
        # INSTANCE variable - unique to each instance
        self.model_name = model_name
        self.accuracy = None
        
        # All instances share and modify the same list
        ModelRegistry.all_models.append(model_name)

# Watch what happens:
model1 = ModelRegistry('RandomForest')
model2 = ModelRegistry('XGBoost')

print(ModelRegistry.all_models)  # ['RandomForest', 'XGBoost']
print(model1.model_name)  # 'RandomForest' - unique to model1
print(model2.model_name)  # 'XGBoost' - unique to model2
```

**Common mistake**: Putting mutable defaults in class definition
```python
# WRONG - all instances will share the same list!
class DataProcessor:
    processed_samples = []  # BAD if you want separate lists per instance

# RIGHT
class DataProcessor:
    def __init__(self):
        self.processed_samples = []  # Each instance gets its own
```

## 3. **When to Use `@staticmethod` and `@classmethod`**

```python
class DataUtils:
    # Regular method - needs instance (self)
    def instance_method(self):
        return self.some_value
    
    # Static method - just a utility function organized in the class
    @staticmethod
    def normalize_array(arr):
        """Doesn't need instance or class data"""
        return (arr - arr.min()) / (arr.max() - arr.min())
    
    # Class method - works with class itself, not instance
    @classmethod
    def from_csv(cls, filepath):
        """Alternative constructor"""
        data = pd.read_csv(filepath)
        return cls(data)  # Creates instance of the class

# Usage:
DataUtils.normalize_array(my_array)  # No instance needed
processor = DataUtils.from_csv('data.csv')  # Alternative way to create instance
```

**In AI/DS**: Static methods are great for preprocessing utilities. Class methods are useful for alternative constructors (like loading models from different sources).

## 4. **Inheritance - Don't Overuse It**

```python
# Base class for all models
class BaseModel:
    def __init__(self):
        self.is_trained = False
    
    def evaluate(self, X, y):
        """Common evaluation logic"""
        predictions = self.predict(X)
        return accuracy_score(y, predictions)
    
    def predict(self, X):
        raise NotImplementedError("Subclass must implement predict()")

# Specific model inherits common functionality
class LogisticRegressionModel(BaseModel):
    def __init__(self, lr=0.01):
        super().__init__()  # Call parent's __init__
        self.lr = lr
        self.weights = None
    
    def predict(self, X):
        # Implement specific prediction logic
        return (X @ self.weights) > 0.5
```

**When to inherit**:
- You have multiple classes sharing significant common behavior
- You're following a framework pattern (like PyTorch's `nn.Module`)

**When NOT to inherit**:
- Just to organize code (use modules/functions instead)
- "Is-a" relationship doesn't make sense

## 5. **Magic Methods / Dunder Methods**

```python
class Dataset:
    def __init__(self, data, labels):
        self.data = data
        self.labels = labels
    
    def __len__(self):
        """Makes len(dataset) work"""
        return len(self.data)
    
    def __getitem__(self, idx):
        """Makes dataset[idx] work - crucial for PyTorch DataLoader!"""
        return self.data[idx], self.labels[idx]
    
    def __repr__(self):
        """String representation for debugging"""
        return f"Dataset(samples={len(self)}, features={self.data.shape[1]})"

# Now you can:
dataset = Dataset(X, y)
print(len(dataset))  # Uses __len__
sample = dataset[0]  # Uses __getitem__
print(dataset)  # Uses __repr__
```

**Most important for AI/DS**:
- `__init__`: Constructor
- `__len__`: Length
- `__getitem__`: Indexing (essential for custom datasets)
- `__repr__` or `__str__`: String representation
- `__call__`: Makes instance callable like a function

## 6. **Composition Over Inheritance**

```python
# Instead of inheriting everything, compose from parts
class DataPipeline:
    def __init__(self):
        self.scaler = StandardScaler()  # Has-a scaler
        self.imputer = SimpleImputer()  # Has-a imputer
        self.encoder = OneHotEncoder()  # Has-a encoder
    
    def fit_transform(self, X):
        X = self.imputer.fit_transform(X)
        X = self.scaler.fit_transform(X)
        X = self.encoder.fit_transform(X)
        return X
```

This is often cleaner than creating complex inheritance hierarchies.

## 7. **Properties - Make Attributes Smart**

```python
class Model:
    def __init__(self):
        self._predictions = None
        self._is_trained = False
    
    @property
    def predictions(self):
        """Computed property"""
        if not self._is_trained:
            raise ValueError("Model not trained yet!")
        return self._predictions
    
    @property
    def num_predictions(self):
        """Another computed property"""
        return len(self._predictions) if self._predictions is not None else 0
    
    @predictions.setter
    def predictions(self, value):
        """Control how predictions are set"""
        if len(value) == 0:
            raise ValueError("Cannot set empty predictions")
        self._predictions = value

# Use like regular attributes but with logic:
model = Model()
# model.predictions  # Would raise error
model._is_trained = True
model.predictions = [1, 2, 3]
print(model.num_predictions)  # 3
```

## 8. **Context Managers for Resource Management**

```python
class ModelCheckpoint:
    def __init__(self, filepath):
        self.filepath = filepath
        self.file = None
    
    def __enter__(self):
        """Called when entering 'with' block"""
        self.file = open(self.filepath, 'w')
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        """Called when exiting 'with' block - always runs"""
        if self.file:
            self.file.close()
    
    def save(self, data):
        self.file.write(data)

# Guarantees cleanup even if error occurs:
with ModelCheckpoint('model.txt') as checkpoint:
    checkpoint.save('weights: [1, 2, 3]')
# File automatically closed here
```

## Quick Memory Aids:

- **Class = Blueprint**, Instance = Actual object built from blueprint
- **`self` = "this specific instance's data"**
- **Instance variable** (in `__init__`) = unique per object
- **Class variable** (outside methods) = shared across all objects
- **Methods that don't use `self`** → probably should be `@staticmethod`
- **Alternative constructors** → use `@classmethod`
- **If unsure**: Start with functions, refactor to class when you find yourself passing the same data to multiple functions
